# ZipAI: AI 기반 청년 주거 안전 플랫폼

**데모 페이지:** https://zipai2026.netlify.app/

---

## 프로젝트 소개

**ZipAI(집아이)**는 청년 및 사회초년생이 안전한 주거를 선택할 수 있도록 지원하는 **AI 기반 청년 주거 안전 플랫폼**입니다. 직방·다방과 같은 매물 탐색 모델을 바탕으로, 전세사기 위험 정보와 지역별 치안 데이터(CCTV, 비상벨, 경찰서 분포 등)를 시각화하여 사용자가 한눈에 안전도를 분석할 수 있습니다.

HTML·CSS·JavaScript 중심의 프론트엔드 프로토타입으로, Leaflet.js 기반 매물 지도, 위험안전도 히트맵, 전세사기 예방 체크리스트·전세가율 계산기, 회원 인증·마이페이지, 고객센터, 관리자 대시보드, 청년 금융지원정책 안내, LH·공공임대 연동, 행복주택 안내 등 주거 탐색부터 안전 계약까지의 사용자 흐름을 구현했습니다.

일부 동적 기능은 `localStorage` 및 가상 JSON 데이터와 연결되어 서버/DB 없이도 찜하기, 체크리스트 진행률, 1:1 문의·관리자 답변 등을 시연할 수 있습니다. Node.js 서버와 Spring Boot 백엔드(Aiven MySQL) 연동을 통해 Excel 매물, LH 공공데이터 API, 회원·매물·문의 등 실서비스 기능도 확장 중입니다.

## 프로젝트 목표

- **지도와 안전 데이터 결합**: 매물 위치 탐색에 치안시설·주의 구간 등 안전 정보를 오버레이로 제공
- **전세사기 자가 진단**: 단계별 체크리스트와 전세가율 연동형 안전성 검증 도구 제공
- **정보 비대칭 해소**: 등기부 확인 요령, 전세보증보험·정부 대출 등 금융 혜택 정보를 한곳에 집약
- **일관된 UX**: 로그인부터 매물 탐색, 안전 진단, 금융 지원, 고객센터까지 통일된 인터페이스 구축
- **반응형 디자인**: PC·태블릿·모바일 등 다양한 해상도에 최적화된 레이아웃 구현

## 기획 의도

대학생·사회초년생이 주거지를 정할 때 가격과 위치를 넘어선 **주거 환경의 안전성**과 **사기 예방의 막막함**이 핵심 과제입니다. 기존 부동산 플랫폼은 거래·매물 정보에 집중되어, 치안 상태나 사기 위험 정보를 확인하려면 경찰청·지자체·등기소 등 여러 출처를 직접 찾아야 합니다.

ZipAI는 **"데이터로 찾고, 안전하게 계약하는 플랫폼"**을 목표로 기획했습니다. 지도에서 CCTV·히트맵을 탐색하고, 계약 단계에서 사기방지 자가진단을 받으며, 청년 금융 지원정책을 확인하는 체계적인 사용자 여정을 통해 청년 주거 복지 향상에 기여하고자 합니다.

## 기술 스택

### Frontend

- **HTML5** · **CSS3** · **JavaScript (ES6+)**: Vanilla JS 기반 DOM 제어, 폼 검증, 반응형 레이아웃(Flexbox/Grid)
- **Leaflet.js**: 지도 패널, 커스텀 마커, 위험구역 폴리곤 오버레이
- **Font Awesome & Bootstrap 5 Icons** · **Google Fonts** (`Noto Sans KR`, `IBM Plex Sans KR`)
- **CSS Custom Properties**: 디자인 토큰 기반 색상·타이포그래피 표준화

### Backend / Infrastructure

- **Node.js**: 정적 파일 제공, Excel 매물 변환, LH 공공데이터 API 중계
- **Java 21 · Spring Boot 3.5.4**: REST API, JPA, Flyway 마이그레이션
- **MySQL 8.4 (Aiven)**: 회원·매물·찜·문의·커뮤니티 등 영속 데이터
- **Web Storage API (`localStorage`)**: 데모용 세션·찜·체크리스트·문의 데이터
- **Netlify** (프론트) · **Render** (백엔드) · **GitHub Pages** (정적 데모)

### Collaboration

- **Git / GitHub** · **GitHub Actions** · **Docker**

## UI 핵심 설계

### 매물 탐색 (메인)

- Leaflet.js 기반 인터랙티브 지도, 줌 레벨별 행정동 집계·개별 마커 전환
- 일반 전·월세 / LH·공공임대 카테고리 분리, 경기도 31개 시·군 기준 검색
- 보증금·월세 슬라이더, 거래 유형·방 유형·부가 옵션(주차, 엘리베이터, 반려동물) 필터
- 슬라이드인 상세 패널, 찜하기(하트) 및 `localStorage` 연동, 매물 등록 모달

### 사기방지 · 계약 안전

- 3단계(계약 전·당일·입주) 12항목 체크리스트 + 실시간 프로그레스 바
- 종합 안전 진단 리포트(점수·등급·보완 행동 가이드)
- 전세가율 계산기(보증금·매매가·근저당 입력 → 위험 등급 카드)
- 계약 시기별 등기부 해독 아코디언 가이드

### 위험안전도

- CCTV·비상벨·파출소·범죄주의구간 커스텀 마커 및 히트맵
- 일반/위성/야간 보행 오버레이 전환, 6대 세부지표(100점 막대그래프) 대시보드
- 주소·지역 검색 기반 종합 안전도 분석 화면

### 금융지원 · 행복주택

- 4대 청년 금융정책(보증보험, 버팀목, 주거금융, 월세 지원) 카드형 안내
- 대상·목적별 맞춤 대출 추천 필터, 대출 한도·금리·상환 스케줄 계산기
- 행복주택 특징·신청 절차 안내, 신청자격 간편진단(나이·소득·자산·무주택 요건)

### 회원 · 고객센터 · 관리자

- 일반 회원 / 공인중개사 탭 가입, 실시간 폼 유효성 검사, 데모 로그인 세션
- 마이페이지(프로필 수정, 찜 목록, 문의 내역), FAQ 검색·1:1 문의 접수
- 관리자 문의 답변·삭제 백오피스(`admin.html`)

### 공통 UX

- 공통 헤더·푸터, 디자인 토큰 기반 일관된 브랜드 톤앤매너
- 데스크톱·태블릿·모바일 반응형 레이아웃, 사기방지 하위 메뉴 활성 상태 표시

## 향후 개발 예정

# ZipAI 프로젝트 안내

ZipAI는 청년과 전·월세 이용자가 집을 찾고 계약 위험을 확인하며, 주거지원정책과 행복주택 정보를 한곳에서 살펴볼 수 있도록 만든 부동산 웹 서비스 데모입니다.

이 문서는 프로젝트에서 구현한 기능, 작업 방식, 실행 방법과 주의사항을 처음 보는 사람도 이해할 수 있도록 정리한 안내서입니다.

## 1. 프로젝트에서 구현한 기능

### 지도 기반 매물 찾기

- 일반 전·월세와 `LH·공공임대`를 별도 카테고리로 구분했습니다.
- 카테고리를 변경하면 매물 목록, 지도 마커, 필터와 안내 문구가 함께 변경됩니다.
- 서비스 범위를 경기도로 제한하고 경기도 31개 시·군을 기준으로 검색·등록하도록 구성했습니다.
- 일반 매물은 거래 유형, 보증금, 월세, 방 유형 등의 조건으로 필터링할 수 있습니다.
- 매물 상세 화면에서 가격, 주소, 면적, 층, 옵션, 출처와 최종 확인일을 확인할 수 있습니다.

### 일반 전·월세 데이터

- `data/admin/성남시_시연용_일반매물_10건.xlsx`의 관리자 매물 10건을 서버에서 읽습니다.
- 서버가 Excel 데이터를 `/api/general-properties` JSON 응답으로 변환합니다.
- 헤더의 `매물 등록` 버튼으로 사용자가 시연용 매물을 추가할 수 있습니다.
- 사용자가 등록한 데이터는 브라우저 `localStorage`에 저장되어 목록과 지도에 바로 반영됩니다.
- 등록자의 자격이나 매물의 실재 여부는 자동 검증하지 않으므로 시연용 기능으로만 사용해야 합니다.

### LH·공공임대 모집공고 연동

- 공공데이터포털의 LH 분양·임대공고 조회 API를 Node 서버에서 호출합니다.
- 경기도 지역 코드 `41`과 모집 상태를 기준으로 공고를 조회합니다.
- 브라우저는 외부 API를 직접 호출하지 않고 프로젝트의 `/api/public-housing`을 호출합니다.
- 인증키가 브라우저에 노출되지 않도록 서버에서만 관리합니다.
- API 응답은 불필요한 반복 호출을 줄이기 위해 10분간 캐시합니다.
- 공고 카드에서 LH청약플러스 원문을 확인할 수 있습니다.
- API에 정확한 건물 좌표가 없는 경우 공고명에서 시·군을 판별해 대표 좌표에 표시합니다. 실제 위치는 반드시 원문 공고에서 확인해야 합니다.

### 사기방지 및 계약 안전 기능

- 계약 안전 진단 결과 페이지
- 단계별 계약 체크리스트
- 매매가와 보증금을 이용한 전세가율 계산기
- 집 알아보기부터 입주 후 보증까지 안내하는 안전 계약가이드
- 각 페이지를 사기방지 하위 메뉴로 연결하고 현재 메뉴가 올바르게 표시되도록 공통 헤더 로직을 구성했습니다.

### 금융지원정책

- 전월세 보증금 대출, 반환보증, 월세지원과 주거급여 정보를 정리했습니다.
- 신청 전 준비사항과 공식 기관 링크를 제공합니다.
- 정책 조건은 변경될 수 있으므로 각 기관의 최신 공고를 최종 기준으로 안내합니다.

### 행복주택 안내

- 전체 상단 메뉴에 `행복주택` 카테고리를 추가했습니다.
- 행복주택의 특징, 주요 공급 대상, 신청 절차와 준비서류를 안내합니다.
- 현재 모집공고 버튼을 LH청약플러스 임대주택 공고 목록에 연결했습니다.
- 계층·소득·자산 조건이 공고마다 다르다는 점과 공식 모집공고가 최종 기준이라는 고지를 표시합니다.

### 행복주택 신청자격 간편진단

행복주택 페이지 안에 다음 항목을 점검하는 자가진단 기능을 구현했습니다.

- 신청 계층 선택
- 모집공고일과 생년월일을 이용한 만 나이 계산
- 무주택 요건 확인
- 재학, 혼인, 수급, 재직 등 계층별 기본요건 확인
- 실제 월평균소득과 사용자가 입력한 공고 상한액 비교
- 총자산 및 자동차가액과 공고 상한액 비교
- 거주지, 학교, 직장 또는 산업단지 연계요건 확인
- 입력 진행률 표시
- 항목별 `통과`, `확인 필요`, `미충족` 결과 제공

금액 비교와 만 나이 계산식은 입력값을 기준으로 계산합니다. 다만 이 기능은 공식 자격 판정기가 아닙니다. 실제 자격은 공급기관이 모집공고일 기준 자료를 사회보장정보시스템 등으로 심사한 결과를 따릅니다.

### AI 생활권 분석

- 사용자가 중요하게 생각하는 생활 조건을 입력하는 화면을 제공합니다.
- 교통, 편의시설 등 생활권 요소를 시각적으로 비교할 수 있도록 구성했습니다.
- 현재 결과는 서비스 흐름과 UI를 확인하기 위한 데모 분석입니다.

### 회원·고객센터·관리자 화면

- 로그인, 회원가입과 마이페이지 화면
- 데모 사용자 정보를 이용한 로그인 상태 표시
- FAQ, 1:1 문의와 문의내역을 포함한 고객센터
- 문의 상태와 답변을 관리하는 관리자 화면
- 공통 헤더, 푸터와 모바일 메뉴

현재 인증과 문의 데이터 일부는 브라우저 저장소를 사용하는 시연용 구조입니다. 실제 운영 전에는 서버 인증과 데이터베이스 연결이 필요합니다.

## 2. 주요 작업 방식

### 프론트엔드

- 별도 UI 프레임워크 없이 HTML, CSS와 JavaScript로 구현했습니다.
- 페이지별 CSS와 JavaScript를 분리했습니다.
- 공통 헤더·푸터 스타일과 인증 UI 로직을 여러 페이지에서 함께 사용합니다.
- 데스크톱, 태블릿과 모바일 화면에 대응하는 반응형 레이아웃을 적용했습니다.
- 긴 한글 제목, 선택창과 결과 카드가 좁은 화면에서 잘리지 않도록 줄바꿈과 입력 레이아웃을 보정했습니다.

### 백엔드

- 별도 웹 프레임워크 없이 Node.js 내장 모듈로 정적 파일과 API를 제공합니다.
- `fetch`로 LH 공공데이터 API를 호출합니다.
- Excel ZIP 내부의 XML을 읽어 관리자 매물을 변환합니다.
- 서비스키는 `.env` 또는 서버 환경변수에서 읽습니다.
- 외부 API 오류, 인증키 미설정과 빈 결과를 JSON 오류로 처리합니다.

### 외부 API를 브라우저에서 직접 호출하지 않는 이유

- 공공데이터 서비스키가 사용자에게 노출될 수 있습니다.
- 다른 사람이 노출된 키를 복사해 호출량을 사용할 수 있습니다.
- 외부 API의 CORS 정책으로 브라우저 요청이 차단될 수 있습니다.
- 캐시, 오류 처리와 호출량 제한을 서버에서 관리하는 편이 안전합니다.

따라서 데이터 흐름은 다음과 같습니다.

```text
브라우저 → ZipAI Node 서버 → 공공데이터포털 LH API
```

PowerShell은 필수 구성요소가 아닙니다. 이전에는 인증키를 임시 환경변수로 전달하는 실행 예시로만 사용했습니다. 현재는 Node 코드가 `.env` 파일을 자동으로 읽습니다.

### Render 환경변수

Render 대시보드에 다음 환경변수를 설정합니다. 실제 비밀번호와 인증키는 저장소나 문서에 기록하지 않습니다.

```env
SERVER_HOST=0.0.0.0
COOKIE_SECURE=true
DB_URL=jdbc:mysql://<aiven-host>:<port>/defaultdb?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Seoul&sslMode=REQUIRED
DB_USERNAME=<aiven-database-user>
DB_PASSWORD=<aiven-database-password>
JAVA_TOOL_OPTIONS=-Xms64m -Xmx320m
PUBLIC_DATA_SERVICE_KEY=<optional-decoded-public-data-key>
```

`PUBLIC_DATA_SERVICE_KEY`가 없으면 나머지 서비스는 실행할 수 있지만 LH 공공임대 API 기능은 사용할 수 없습니다.

### 데이터베이스 초기화

Spring Boot가 Aiven MySQL에 처음 연결되면 Flyway가 `src/main/resources/db/migration`의 SQL을 실행하여 사용자, 매물, 찜, 방문 예약, 커뮤니티, 문의 및 알림 테이블을 생성합니다. 운영 데이터베이스에는 `ddl-auto: validate`를 사용합니다.

### 보안 주의사항

- Aiven 로그인 비밀번호가 아닌 MySQL 전용 접속 비밀번호를 `DB_PASSWORD`로 사용합니다.
- 데이터베이스 비밀번호와 API 키는 Render 환경변수에만 저장합니다.
- `.env`, 실제 인증서 및 비밀값을 Git에 커밋하지 않습니다.
- Aiven 연결에는 `sslMode=REQUIRED`를 사용합니다.
- Render 무료 서비스는 고정 송신 IP가 없으므로 현재 Aiven IP 필터를 특정 Render IP로 제한할 수 없습니다. 운영 규모가 커지면 고정 IP 또는 사설 네트워크 환경으로 이전합니다.

### 무료 플랜 제한

- Render 무료 Web Service는 일정 시간 요청이 없으면 중지되며 첫 요청 시 재시작에 약 1분이 걸릴 수 있습니다.
- Render 무료 인스턴스는 512MB RAM과 제한된 CPU를 사용하므로 Java 힙을 `-Xms64m -Xmx320m`으로 제한했습니다.
- Aiven 무료 MySQL은 학습, 시연 및 소규모 프로젝트 용도이며 저장공간과 성능에 제한이 있습니다.
- 트래픽과 데이터가 증가하면 유료 관리형 서비스 또는 EC2 등 별도 인프라로 이전해야 합니다.

## 플랫폼 실행 및 장애 복구 운영 가이드

이 절은 시간이 지난 뒤 다시 실행하거나 다른 컴퓨터에서 프로젝트를 이어받을 때 확인할 항목을 정리한 운영용 안내서입니다.

### 서버 실행 전 반드시 수행할 작업

플랫폼 서버를 실행하기 전에 **Aiven MySQL을 먼저 켜야 합니다.** 데이터베이스가 `OFF`인 상태에서는 Render 백엔드가 데이터베이스에 연결할 수 없어 로그인, 회원가입, 매물, 찜, 문의 등 서버 기능이 작동하지 않습니다.

다음 순서대로 실행합니다.

#### 1단계: Aiven MySQL 전원 켜기

1. [Aiven Console](https://console.aiven.io/)에 로그인합니다.
2. 프로젝트 목록에서 ZipAI가 사용하는 프로젝트를 선택합니다.
3. 서비스 목록에서 ZipAI MySQL 서비스를 선택합니다.
4. 서비스 상태가 `OFF`, `POWERED OFF` 또는 중지 상태인지 확인합니다.
5. 꺼져 있다면 `Power on`, `Start service` 또는 서비스 시작 버튼을 누릅니다.
6. 서비스 상태가 `REBUILDING`, `STARTING` 또는 준비 중으로 표시되면 바로 Render를 실행하지 말고 기다립니다.
7. 최종 상태가 반드시 `RUNNING`이 되었는지 확인합니다.

```text
Aiven MySQL
OFF
  ↓ Power on 또는 Start service
STARTING / REBUILDING
  ↓ 잠시 대기
RUNNING
```

`RUNNING`이 되기 전에 Render 서버를 시작하면 DB 연결 오류가 발생할 수 있습니다.

#### 2단계: Aiven 연결정보 확인

Aiven MySQL 서비스 화면의 연결정보에서 다음 값이 존재하는지 확인합니다.

- Host
- Port
- Database name
- User
- Password
- SSL 사용 상태

비밀번호를 재설정했거나 서비스 연결정보가 바뀌었다면 Render의 `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`도 같은 값으로 수정해야 합니다.

#### 3단계: Render 백엔드 실행

1. [Render Dashboard](https://dashboard.render.com/)에 로그인합니다.
2. `zipai-api` Web Service를 선택합니다.
3. 서비스가 중지되어 있다면 `Resume`, `Restart service` 또는 서비스 시작 기능을 실행합니다.
4. 코드가 변경되었다면 최신 커밋을 선택해 `Manual Deploy`를 실행합니다.
5. Render의 `Logs`를 열고 Spring Boot가 정상적으로 시작되는지 확인합니다.
6. 다음 상태 확인 주소를 엽니다.

```text
https://zipai-jb4z.onrender.com/api/health
```

다음 응답이 나오면 Render 백엔드가 정상 실행된 것입니다.

```json
{"status":"ok"}
```

#### 4단계: Netlify에서 최종 연결 확인

1. Netlify Production URL을 엽니다.
2. Production URL 뒤에 `/api/health`를 붙여 접속합니다.

```text
https://<netlify-production-domain>/api/health
```

3. `{"status":"ok"}`가 나오면 `Netlify → Render → Aiven` 연결이 모두 정상입니다.
4. 마지막으로 로그인, 매물 조회, 찜하기 또는 문의 기능 중 하나를 직접 실행해 DB 읽기·쓰기를 확인합니다.

#### 서버 시작 순서 한 줄 요약

```text
Aiven 로그인
  → MySQL OFF 확인
  → Power on
  → RUNNING 확인
  → Render zipai-api 시작 또는 재시작
  → Render /api/health 확인
  → Netlify /api/health 확인
  → 로그인 등 실제 기능 확인
```

체크리스트:

- [ ] Aiven MySQL이 `OFF`가 아닌지 확인
- [ ] 꺼져 있으면 `Power on` 또는 `Start service` 실행
- [ ] Aiven 상태가 `RUNNING`이 될 때까지 대기
- [ ] Render의 DB 환경변수가 Aiven 연결정보와 같은지 확인
- [ ] Render `zipai-api` 시작·재시작 또는 Manual Deploy
- [ ] Render 직접 주소의 `/api/health` 정상 응답 확인
- [ ] Netlify 주소의 `/api/health` 정상 응답 확인
- [ ] 로그인 또는 데이터 저장 기능으로 최종 확인

### 1. 먼저 기억할 운영 구조

```text
사용자 브라우저
  ↓
Netlify: 화면 파일 제공
  ↓ /api/* 요청 전달
Render: Spring Boot 백엔드 실행
  ↓ JDBC + SSL
Aiven: MySQL 데이터 저장
```

세 서비스 중 하나라도 중지되거나 연결정보가 달라지면 일부 또는 전체 기능이 동작하지 않을 수 있습니다.

| 증상                                         | 먼저 확인할 서비스                           |
| -------------------------------------------- | -------------------------------------------- |
| 사이트 자체가 열리지 않음                    | Netlify                                      |
| 화면은 열리지만 로그인·찜·문의 등이 실패함 | Render                                       |
| Render가 실행되지 않거나 DB 오류가 발생함    | Aiven 및 Render 환경변수                     |
| 일반 기능은 되지만 LH 공고만 나오지 않음     | `PUBLIC_DATA_SERVICE_KEY`와 공공데이터포털 |
| 지도만 나오지 않음                           | Naver Maps 허용 도메인과 클라이언트 ID 설정  |

### 2. 운영 사이트를 평소에 실행하는 방법

Netlify와 Aiven은 정상 상태이고 Render 무료 서버만 절전 상태라면 별도의 프로그램을 실행할 필요가 없습니다.

1. Netlify Production URL에 접속합니다.
2. 첫 화면이 열린 뒤 로그인 등 서버 기능을 실행합니다.
3. Render 무료 서비스가 잠들어 있었다면 첫 요청 후 약 1분 정도 기다립니다.
4. 다음 주소를 새로 열어 백엔드가 깨어났는지 확인합니다.

```text
https://zipai-jb4z.onrender.com/api/health
```

정상 응답은 다음과 같습니다.

```json
{"status":"ok"}
```

5. Netlify 프록시도 정상인지 Production URL 뒤에 `/api/health`를 붙여 확인합니다.

```text
https://<netlify-production-domain>/api/health
```

### 3. Aiven MySQL에서 확인할 작업

Aiven은 회원·매물·찜·문의·예약·커뮤니티 데이터를 보관합니다. Aiven 서비스가 중지되었거나 접속정보가 바뀌면 Render 백엔드는 정상적으로 시작할 수 없습니다.

1. Aiven Console에 로그인합니다.
2. ZipAI가 사용하는 MySQL 서비스를 선택합니다.
3. 서비스 상태가 `RUNNING`인지 확인합니다.
4. 중지 또는 전원 꺼짐 상태라면 서비스 시작 또는 전원 켜기 작업을 수행합니다.
5. 서비스의 연결정보에서 다음 값을 확인합니다.

```text
Host
Port
Database name
User
Password
SSL 사용 여부
```

6. 위 정보를 이용해 Render의 `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`가 현재 값과 같은지 확인합니다.

Render에 입력하는 JDBC 주소 형식은 다음과 같습니다.

```text
jdbc:mysql://<aiven-host>:<port>/<database-name>?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Seoul&sslMode=REQUIRED
```

7. Aiven의 IP 접근 제한 기능을 사용 중이면 Render에서 접속 가능한 설정인지 확인합니다. Render 무료 서비스는 고정 송신 IP를 제공하지 않으므로 특정 IP만 허용하면 연결이 실패할 수 있습니다.

주의사항:

- Aiven 웹사이트 로그인 비밀번호와 MySQL 접속 비밀번호는 서로 다를 수 있습니다.
- MySQL 비밀번호를 변경했다면 Render의 `DB_PASSWORD`도 반드시 함께 변경합니다.
- 비밀번호와 전체 접속주소를 README, Git 커밋 또는 화면 캡처에 남기지 않습니다.
- Flyway가 최초 연결 시 테이블을 생성하므로 운영 DB의 스키마를 임의로 삭제하지 않습니다.

### 4. Render 백엔드에서 확인할 작업

1. Render Dashboard에 로그인합니다.
2. `zipai-api` Web Service를 선택합니다.
3. 서비스 상태와 최근 배포 결과가 정상인지 확인합니다.
4. `Environment`에서 다음 환경변수를 확인합니다.

```env
SERVER_HOST=0.0.0.0
COOKIE_SECURE=true
DB_URL=<Aiven JDBC URL>
DB_USERNAME=<Aiven MySQL 사용자>
DB_PASSWORD=<Aiven MySQL 비밀번호>
PUBLIC_DATA_SERVICE_KEY=<공공데이터포털 Decoding 인증키>
JAVA_TOOL_OPTIONS=-Xms64m -Xmx320m
```

`PORT`는 Render가 자동으로 주입하므로 직접 고정하지 않는 것이 좋습니다.

5. 환경변수를 수정했다면 저장 후 새 배포 또는 서비스 재시작을 수행합니다.
6. 코드가 GitHub에 반영되었는데 운영 서비스가 예전 버전이라면 최신 커밋으로 `Manual Deploy`를 실행합니다.
7. 배포가 실패하면 Render의 `Logs`에서 가장 먼저 발생한 오류를 확인합니다.

대표적인 로그와 조치:

| 로그 또는 증상                  | 원인 및 조치                                                   |
| ------------------------------- | -------------------------------------------------------------- |
| `Communications link failure` | Aiven이 실행 중인지, 호스트·포트·IP 접근 제한을 확인         |
| `Access denied for user`      | `DB_USERNAME`과 `DB_PASSWORD`를 Aiven 연결정보와 다시 비교 |
| SSL 관련 오류                   | `DB_URL`에 `sslMode=REQUIRED`가 포함됐는지 확인            |
| Flyway validation 오류          | DB 스키마를 수동 변경했는지 확인하고 마이그레이션 파일과 비교  |
| 메모리 부족 또는 강제 종료      | `JAVA_TOOL_OPTIONS=-Xms64m -Xmx320m` 확인                    |
| LH API만 실패                   | `PUBLIC_DATA_SERVICE_KEY`가 Decoding 키인지 확인             |

### 5. Netlify 프론트엔드에서 확인할 작업

1. Netlify Dashboard에서 ZipAI 사이트를 선택합니다.
2. 최근 Production Deploy가 성공했는지 확인합니다.
3. GitHub의 최신 커밋이 반영되지 않았다면 새 배포를 실행합니다.
4. `netlify.toml`의 프록시 대상이 현재 Render 주소와 같은지 확인합니다.

```toml
[[redirects]]
  from = "/api/*"
  to = "https://zipai-jb4z.onrender.com/api/:splat"
  status = 200
  force = true
```

5. Render 서비스 주소가 변경되면 위 주소를 수정하고 Netlify를 다시 배포합니다.
6. Netlify Production URL의 `/api/health`가 Render의 상태 응답을 반환하는지 확인합니다.
7. 지도 기능이 실패하면 Naver Cloud Platform의 Maps 설정에서 현재 Netlify 도메인이 허용 도메인으로 등록되어 있는지 확인합니다.

### 6. 다른 컴퓨터에서 로컬로 실행하는 방법

#### 필요한 프로그램

- Git
- Java 21
- 프로젝트에 포함된 Gradle Wrapper
- MySQL 8 이상 또는 접근 가능한 Aiven MySQL

Node.js 서버는 과거 데모용 구현이며, 현재 운영 구조와 동일하게 확인하려면 Spring Boot 애플리케이션을 실행합니다.

#### 저장소 준비

```powershell
git clone <repository-url>
Set-Location zipai
git pull
java -version
```

`java -version`에서 Java 21이 확인되어야 합니다.

#### 방법 A: 로컬 MySQL 사용

1. MySQL에 `zipai` 데이터베이스와 전용 사용자를 생성합니다.
2. 현재 PowerShell 창에 환경변수를 설정합니다.

```powershell
$env:SERVER_HOST='127.0.0.1'
$env:SERVER_PORT='4173'
$env:COOKIE_SECURE='false'
$env:DB_URL='jdbc:mysql://127.0.0.1:3306/zipai?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Seoul&allowPublicKeyRetrieval=true'
$env:DB_USERNAME='zipai'
$env:DB_PASSWORD='<local-mysql-password>'
$env:PUBLIC_DATA_SERVICE_KEY='<optional-decoded-public-data-key>'
.\gradlew.bat bootRun
```

3. 브라우저에서 다음 주소를 엽니다.

```text
http://127.0.0.1:4173
http://127.0.0.1:4173/api/health
```

#### 방법 B: 다른 컴퓨터에서 Aiven DB에 직접 연결

로컬 MySQL을 설치하지 않고 Aiven을 사용할 수도 있습니다. Aiven 서비스가 실행 중이어야 하며 접속정보를 외부에 노출하지 않도록 주의합니다.

```powershell
$env:SERVER_HOST='127.0.0.1'
$env:SERVER_PORT='4173'
$env:COOKIE_SECURE='false'
$env:DB_URL='jdbc:mysql://<aiven-host>:<port>/<database-name>?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Seoul&sslMode=REQUIRED'
$env:DB_USERNAME='<aiven-user>'
$env:DB_PASSWORD='<aiven-mysql-password>'
$env:PUBLIC_DATA_SERVICE_KEY='<optional-decoded-public-data-key>'
.\gradlew.bat bootRun
```

중요: `.env.example`은 필요한 변수의 예시 파일입니다. 비밀값을 입력한 `.env`를 Git에 커밋하지 않으며, Spring Boot를 PowerShell에서 실행할 때는 위와 같이 현재 터미널에 환경변수를 설정하는 방식이 가장 확실합니다.

### 7. 다른 컴퓨터에서 코드 변경 후 배포하는 방법

1. 로컬에서 변경하고 테스트합니다.

```powershell
.\gradlew.bat test
.\gradlew.bat bootJar
```

2. GitHub에 커밋과 푸시를 수행합니다.
3. GitHub Actions 빌드가 성공했는지 확인합니다.
