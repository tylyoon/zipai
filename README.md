# ZipAI 프로젝트 안내

ZipAI는 청년과 전·월세 이용자가 집을 찾고 계약 위험을 확인하며, 주거지원정책과 행복주택 정보를 한곳에서 살펴볼 수 있도록 만든 부동산 웹 서비스 데모입니다.

이 문서는 프로젝트에서 구현한 기능, 작업 방식, 실행 방법과 주의사항을 처음 보는 사람도 이해할 수 있도록 정리한 안내서입니다.

## 1. 프로젝트에서 구현한 기능

### 지도 기반 매물 찾기

- 일반 전·월세와 `LH·공공임대`를 별도 카테고리로 구분했습니다.
- 카테고리를 변경하면 매물 목록, 지도 마커, 필터와 안내 문구가 함께 변경됩니다.
- 서비스 범위를 경기도로 제한하고 경기도 31개 시·군을 기준으로 검색·등록하도록 구성했습니다.
- 일반 매물은 거래 유형, 보증금, 월세, 방 유형 등의 조건으로 필터링할 수 있습니다.
- 매물 상세 화면에서 가격, 주소, 면적, 층, 옵션, 출처와 최종 확인일을 확인할 수 있습니다.

### 일반 전·월세 데이터

- `data/admin/성남시_시연용_일반매물_10건.xlsx`의 관리자 매물 10건을 서버에서 읽습니다.
- 서버가 Excel 데이터를 `/api/general-properties` JSON 응답으로 변환합니다.
- 헤더의 `매물 등록` 버튼으로 사용자가 시연용 매물을 추가할 수 있습니다.
- 사용자가 등록한 데이터는 브라우저 `localStorage`에 저장되어 목록과 지도에 바로 반영됩니다.
- 등록자의 자격이나 매물의 실재 여부는 자동 검증하지 않으므로 시연용 기능으로만 사용해야 합니다.

### LH·공공임대 모집공고 연동

- 공공데이터포털의 LH 분양·임대공고 조회 API를 Node 서버에서 호출합니다.
- 경기도 지역 코드 `41`과 모집 상태를 기준으로 공고를 조회합니다.
- 브라우저는 외부 API를 직접 호출하지 않고 프로젝트의 `/api/public-housing`을 호출합니다.
- 인증키가 브라우저에 노출되지 않도록 서버에서만 관리합니다.
- API 응답은 불필요한 반복 호출을 줄이기 위해 10분간 캐시합니다.
- 공고 카드에서 LH청약플러스 원문을 확인할 수 있습니다.
- API에 정확한 건물 좌표가 없는 경우 공고명에서 시·군을 판별해 대표 좌표에 표시합니다. 실제 위치는 반드시 원문 공고에서 확인해야 합니다.

### 사기방지 및 계약 안전 기능

- 계약 안전 진단 결과 페이지
- 단계별 계약 체크리스트
- 매매가와 보증금을 이용한 전세가율 계산기
- 집 알아보기부터 입주 후 보증까지 안내하는 안전 계약가이드
- 각 페이지를 사기방지 하위 메뉴로 연결하고 현재 메뉴가 올바르게 표시되도록 공통 헤더 로직을 구성했습니다.

### 금융지원정책

- 전월세 보증금 대출, 반환보증, 월세지원과 주거급여 정보를 정리했습니다.
- 신청 전 준비사항과 공식 기관 링크를 제공합니다.
- 정책 조건은 변경될 수 있으므로 각 기관의 최신 공고를 최종 기준으로 안내합니다.

### 행복주택 안내

- 전체 상단 메뉴에 `행복주택` 카테고리를 추가했습니다.
- 행복주택의 특징, 주요 공급 대상, 신청 절차와 준비서류를 안내합니다.
- 현재 모집공고 버튼을 LH청약플러스 임대주택 공고 목록에 연결했습니다.
- 계층·소득·자산 조건이 공고마다 다르다는 점과 공식 모집공고가 최종 기준이라는 고지를 표시합니다.

### 행복주택 신청자격 간편진단

행복주택 페이지 안에 다음 항목을 점검하는 자가진단 기능을 구현했습니다.

- 신청 계층 선택
- 모집공고일과 생년월일을 이용한 만 나이 계산
- 무주택 요건 확인
- 재학, 혼인, 수급, 재직 등 계층별 기본요건 확인
- 실제 월평균소득과 사용자가 입력한 공고 상한액 비교
- 총자산 및 자동차가액과 공고 상한액 비교
- 거주지, 학교, 직장 또는 산업단지 연계요건 확인
- 입력 진행률 표시
- 항목별 `통과`, `확인 필요`, `미충족` 결과 제공

금액 비교와 만 나이 계산식은 입력값을 기준으로 계산합니다. 다만 이 기능은 공식 자격 판정기가 아닙니다. 실제 자격은 공급기관이 모집공고일 기준 자료를 사회보장정보시스템 등으로 심사한 결과를 따릅니다.

### AI 생활권 분석

- 사용자가 중요하게 생각하는 생활 조건을 입력하는 화면을 제공합니다.
- 교통, 편의시설 등 생활권 요소를 시각적으로 비교할 수 있도록 구성했습니다.
- 현재 결과는 서비스 흐름과 UI를 확인하기 위한 데모 분석입니다.

### 회원·고객센터·관리자 화면

- 로그인, 회원가입과 마이페이지 화면
- 데모 사용자 정보를 이용한 로그인 상태 표시
- FAQ, 1:1 문의와 문의내역을 포함한 고객센터
- 문의 상태와 답변을 관리하는 관리자 화면
- 공통 헤더, 푸터와 모바일 메뉴

현재 인증과 문의 데이터 일부는 브라우저 저장소를 사용하는 시연용 구조입니다. 실제 운영 전에는 서버 인증과 데이터베이스 연결이 필요합니다.

## 2. 주요 작업 방식

### 프론트엔드

- 별도 UI 프레임워크 없이 HTML, CSS와 JavaScript로 구현했습니다.
- 페이지별 CSS와 JavaScript를 분리했습니다.
- 공통 헤더·푸터 스타일과 인증 UI 로직을 여러 페이지에서 함께 사용합니다.
- 데스크톱, 태블릿과 모바일 화면에 대응하는 반응형 레이아웃을 적용했습니다.
- 긴 한글 제목, 선택창과 결과 카드가 좁은 화면에서 잘리지 않도록 줄바꿈과 입력 레이아웃을 보정했습니다.

### 백엔드

- 별도 웹 프레임워크 없이 Node.js 내장 모듈로 정적 파일과 API를 제공합니다.
- `fetch`로 LH 공공데이터 API를 호출합니다.
- Excel ZIP 내부의 XML을 읽어 관리자 매물을 변환합니다.
- 서비스키는 `.env` 또는 서버 환경변수에서 읽습니다.
- 외부 API 오류, 인증키 미설정과 빈 결과를 JSON 오류로 처리합니다.

### 외부 API를 브라우저에서 직접 호출하지 않는 이유

- 공공데이터 서비스키가 사용자에게 노출될 수 있습니다.
- 다른 사람이 노출된 키를 복사해 호출량을 사용할 수 있습니다.
- 외부 API의 CORS 정책으로 브라우저 요청이 차단될 수 있습니다.
- 캐시, 오류 처리와 호출량 제한을 서버에서 관리하는 편이 안전합니다.

따라서 데이터 흐름은 다음과 같습니다.

```text
브라우저 → ZipAI Node 서버 → 공공데이터포털 LH API
```

PowerShell은 필수 구성요소가 아닙니다. 이전에는 인증키를 임시 환경변수로 전달하는 실행 예시로만 사용했습니다. 현재는 Node 코드가 `.env` 파일을 자동으로 읽습니다.

## 4. 실행 방법

### 준비사항

- Node.js 18 이상
- LH 공공임대 실제 데이터를 사용할 경우 공공데이터포털 인증키

별도의 npm 패키지 설치는 필요하지 않습니다.

### 기본 실행

프로젝트 폴더에서 다음 명령을 실행합니다.

```text
node server.js
```

브라우저에서 다음 주소로 접속합니다.

```text
http://127.0.0.1:4173
```

`index.html` 파일을 직접 열면 일부 정적 화면은 볼 수 있지만 Excel 매물과 LH API는 서버 경로를 사용하므로 반드시 Node 서버로 접속하는 것이 좋습니다.

## 5. LH 공공데이터 연결 방법

### 1단계: 인증키 발급

공공데이터포털에서 LH 분양·임대공고 조회 서비스의 활용을 신청하고 `일반 인증키(Decoding)`를 발급받습니다.

### 2단계: `.env` 파일 생성

프로젝트의 `.env.example`을 복사하여 파일명을 `.env`로 변경합니다.

```env
PUBLIC_DATA_SERVICE_KEY=발급받은_일반인증키_Decoding
PORT=4173
```

값을 따옴표로 감싸지 않아도 됩니다. 실제 `.env` 파일은 `.gitignore`에 등록되어 Git에 포함되지 않습니다.

### 3단계: 서버 재시작

```text
node server.js
```

메인 화면에서 `LH·공공임대` 카테고리를 선택하면 `/api/public-housing`을 통해 데이터를 불러옵니다.

### 다른 방식의 환경변수

배포 환경에서 이미 환경변수를 제공한다면 `.env`보다 서버 환경변수가 우선 적용됩니다.

```text
PUBLIC_DATA_SERVICE_KEY
PORT
```

## 6. 서버 API

| 경로 | 방식 | 설명 |
| --- | --- | --- |
| `/api/general-properties` | GET | 관리자 Excel의 일반 매물 반환 |
| `/api/public-housing` | GET | LH 공공임대 공고 조회 및 정규화 결과 반환 |

서비스키가 설정되지 않은 상태에서 `/api/public-housing`을 호출하면 설정 안내가 포함된 오류 응답을 반환합니다. 임의의 가짜 공고는 표시하지 않습니다.

## 7. 정보 이용 시 주의사항

- 행복주택의 소득·자산·무주택·지역 기준은 계층과 모집공고에 따라 달라집니다.
- 자가진단은 사용자가 입력한 값의 단순 비교와 사전 점검 결과입니다.
- `신청 가능성이 높음`은 자격, 순위, 당첨 또는 계약을 보장하지 않습니다.
- LH 공고의 신청 일정, 임대조건, 제출서류와 실제 주소는 원문 공고를 최종 기준으로 확인해야 합니다.
- 전세가율과 안전점수는 법률·감정평가 또는 보증가입 심사를 대신하지 않습니다.
- 초기 예시 매물과 일부 분석 결과는 화면 시연용 데이터입니다.
- 주민등록번호, 인증서, 정확한 자산내역 같은 민감정보를 현재 데모 화면에 입력하거나 저장하지 마세요.

## 8. 현재 한계

- 일반 매물 등록 자료가 사용자 브라우저에만 저장됩니다.
- 여러 사용자가 공유하는 데이터베이스가 없습니다.
- 정확한 주소를 위·경도로 변환하는 지오코딩이 연결되어 있지 않습니다.
- 공인중개사 자격과 매물 소유 관계를 검증하지 않습니다.
- 사진 파일과 상담 신청 내용이 서버에 저장되지 않습니다.
- LH 공고의 세대별 임대료와 상세 자격을 자동 추출하지 않습니다.
- 행복주택 자가진단이 특정 모집공고의 조건을 자동으로 불러오지는 않습니다.
- 로그인과 일부 관리자 기능은 실제 보안 인증이 아닌 데모 방식입니다.

## 9. 실제 서비스 전환 시 필요한 작업

- 사용자·매물·문의용 데이터베이스 구축
- 비밀번호 암호화와 서버 세션 또는 토큰 인증
- 공인중개사 및 매물 소유 관계 검증
- 관리자 승인, 수정, 거래완료와 자동 만료 처리
- 도로명주소 검색과 정확한 좌표 변환
- 사진 저장소와 업로드 보안 검사
- 허위매물 신고 및 제재 기능
